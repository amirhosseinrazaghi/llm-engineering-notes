# 🐞 باگ‌ها و راه‌حل‌هاشون

## ۱. کدرانر آدرس محیط مجازی رو نمی‌شناخت

**مشکل:** تو `executorMap` فقط مسیر پوشه محیط مجازی رو گذاشته بودم، نه مسیر فایل اجرایی پایتون داخلش. **راه‌حل:** باید تا خودِ `Scripts\python.exe` بری، بعدش `-u $fullFileName` رو اضافه کنی:

```json
"code-runner.executorMap": {
    "python": "مسیر\\کامل\\تا\\Scripts\\python.exe -u $fullFileName"
}
```

## ۲. پکیج `dotenv` نصب بود ولی import نمی‌شد

**مشکل:** پکیج اشتباه نصب کرده بودم. `dotenv` و `python-dotenv` دو تا پکیج جدا هستن. **راه‌حل:**

```
pipenv uninstall dotenv
pipenv install python-dotenv
```

نکته: بعد از نصب بازم می‌نویسی `import dotenv` — اسم پکیج با اسم import فرق داره.

## ۳. ویژوال استودیو کد از پایتونِ درست استفاده نمی‌کرد

**مشکل:** اینتروپرتر انتخاب‌شده تو ویژوال استودیو کد، همون محیط مجازی pipenv نبود. **راه‌حل:** با `Ctrl+Shift+P` برو `Python: Select Interpreter` و مسیر `Scripts\python.exe` محیط مجازی رو دستی وارد کن (از `pipenv --venv` مسیرشو بگیر).

## ۴. مدل جواب نمی‌داد، فقط یه عدد کوچیک برمی‌گردوند

**مشکل:** مدل انتخابی (`llama-prompt-guard-2-86m`) اصلاً یه مدل مکالمه‌ای نبود؛ یه مدل امنیتیه که فقط احتمال «خطرناک بودن» پیام رو برمی‌گردونه. **راه‌حل:** اسم مدل رو به یه مدل مکالمه‌ای واقعی عوض کردم (مثل `llama-3.1-8b-instant`).

## ۵. گراک همیشه ۴۰۳ Forbidden می‌داد

**مشکل:** حتی ساده‌ترین درخواست (لیست مدل‌ها) هم ۴۰۳ خشک می‌داد، بدون توضیح. کلید API هم درست لود می‌شد. این یعنی مسدودیت جغرافیایی — گراک از منطقه من دسترسی نمی‌داد. **راه‌حل:** به‌جای گراک، رفتم سراغ OpenRouter (سرویس جایگزین که این محدودیت رو نداشت). فقط کافی بود `base_url`، کلید، و اسم مدل عوض بشه:

```python
base_url="https://openrouter.ai/api/v1"
```

## ۶. مدل رایگان OpenRouter خطای ۴۰۴ می‌داد

**مشکل:** مدل `meta-llama/llama-3.1-8b-instruct:free` دیگه نسخه رایگان نداشت (فقط پولیش موجود بود). **راه‌حل:** رفتم سراغ یه مدل دیگه که هنوز رایگان بود (`openai/gpt-oss-120b:free`). نکته مهم: لیست مدل‌های رایگان OpenRouter مدام عوض می‌شه، پس بهتره چند مدل جایگزین رو با هم بدی تا اگه یکی از رده خارج شد، خودکار بره سراغ بعدی.

## ۷. مدل جمله رو نمی‌فهمید — `messages=message` به‌جای `messages=messages`

**مشکل:** تو تابع `bot`، پارامتر ورودی تابع (مفرد، یه رشته متنی خام مثل `"hi"`) رو مستقیم به `messages` می‌فرستادم، به‌جای اینکه لیست کامل تاریخچه گفتگو رو بفرستم. **راه‌حل:** اسم متغیر رو درست کردم:

```python
response = llm.chat.completions.create(
    model="...",
    messages=messages,   # لیست کامل، نه پیام مفرد
)
```

**درسش:** این باگ خطای ۴۰۰ (Bad Request) داد چون سرور اصلاً نفهمید چی گرفته — همیشه وقتی خطای ۴۰۰ می‌گیری، اول مقدار واقعی چیزی که می‌فرستی رو با `print()` چک کن.

## ۸. مدل رایگان یهو ۴۲۹ (Rate Limit) داد

**مشکل:** مدل `google/gemma-4-26b-a4b-it:free` وسط کار یهو خطای «موقتاً محدود شده» داد، بدون هیچ تغییری تو کد خودم. **راه‌حل:** این ربطی به کد نداشت — سهمیه رایگان این مدل بین همه کاربرهای دنیا مشترکه و لحظه‌ای پر شده بود. با اضافه‌کردن چند مدل پشتیبان تو `extra_body` حلش کردم تا اگه یکی شلوغ بود خودکار بره سراغ بعدی:

```python
extra_body={
    "models": ["مدل اول:free", "مدل دوم:free", "مدل سوم:free"]
}
```

**نکته:** این باگ دوباره هم پیش اومد (این‌بار با یه مدل دیگه) — یعنی جزو محدودیت‌های همیشگی مدل‌های رایگانه، نه یه اتفاق یه‌بارمصرف. باید همیشه چند مدل پشتیبان آماده داشته باشم.

## ۹. `trim_messages` به‌جای کوتاه‌کردن تاریخچه، خرابش کرد

**مشکل:** برای محدودکردن طول تاریخچه گفتگو (و کاهش هزینه)، یه متد `trim_messages` اضافه کردم، ولی دو تا اشتباه توش بود:

۱. شرط برعکس بود: `if len(self.messages) > max_number: return` — یعنی وقتی واقعاً لازم بود کوتاه بشه، هیچ کاری نمی‌کرد، و وقتی لازم نبود، کد کوتاه‌کردن اجرا می‌شد. ۲. خط آخر متد، به‌جای چسبوندن دو لیست به هم، اونا رو به‌عنوان دو عضو یه لیست بیرونی می‌ذاشت:

```python
self.messages = [system_messages, trimed_messages]  # اشتباه: لیستِ لیست‌ها
```

در نتیجه `self.messages[0]` دیگه یه پیام (دیکشنری) نبود، خودش یه لیست بود — همین باعث خطای ۴۰۰ با پیام دقیق `messages.0: expected object, received array` شد.

**راه‌حل (نسخه‌ی نهایی که خودم نوشتم):**

```python
def trim_messages(self, max_number=4):
    if len(self.messages) < max_number:
        return

    system_messages = [m for m in self.messages if m['role'] == 'system']
    other_messages = [m for m in self.messages if m['role'] != 'system']

    trimed_messages = other_messages[-max_number:]

    self.messages = [*system_messages, *trimed_messages]
```

نکته درباره `*`: به‌جای `+` (که هم جواب می‌ده)، اینجا از عملگر **unpacking** استفاده شده — هر عضو داخل `system_messages` و `trimed_messages` رو تک‌تک از داخل لیستشون بیرون می‌کشه و مستقیم تو لیست جدید می‌ذاره؛ نتیجه‌اش با `+` یکیه، فقط `*` انعطاف بیشتری داره (می‌تونی چند لیست/تاپل مختلف رو با هم تو یه لیست جدید قاطی کنی، نه فقط دوتا).

**درسش:** وقتی خطای ۴۰۰ می‌گیری، پیام سرور اکثراً دقیقاً می‌گه کدوم فیلد ساختارش خرابه (مثل `messages.0`) — این خیلی سریع‌تر از حدس‌زدنه، مستقیم برو همون‌جا رو چک کن. همچنین: هروقت یه لیست از دیکشنری‌ها رو داری با یه لیست دیگه ترکیب می‌کنی، همیشه بین `+` (چسبوندن) و `[a, b]` (تو‌دیگری‌گذاشتن) دقت کن — این دو تا ساختار خروجی کاملاً متفاوتی می‌سازن.

## ۱۰. `other_messages[5:0]` باعث شد پیام‌های اخیر کامل پاک بشن

**مشکل:** تو متد `summerize`، برای جدا کردن پیام‌های قدیمی (که باید خلاصه بشن) از پیام‌های اخیر (که باید دست‌نخورده بمونن)، نوشته بودم:

```python
early_messages, last_messages = (
    other_messages[0:5], other_messages[5:0])
```

`other_messages[5:0]` یعنی «از ایندکس ۵ شروع کن، تا قبل از ایندکس ۰ برو». چون این جهت برعکسه (شروع بزرگ‌تر از پایان، با قدم پیش‌فرض مثبت)، پایتون همیشه یه لیست **خالی** برمی‌گردونه. یعنی `last_messages` همیشه `[]` بود — هر بار خلاصه‌سازی اجرا می‌شد، همه‌ی پیام‌های اخیر (همونایی که قرار بود دست‌نخورده بمونن) کامل از تاریخچه پاک می‌شدن، نه فقط قدیمی‌ها.

**راه‌حل:**

```python
early_messages, last_messages = (
    other_messages[0:5], other_messages[5:])
```

فقط کافی بود عدد `0` بعد از `:` حذف بشه — `[5:]` یعنی «از ایندکس ۵ تا آخر لیست»، برخلاف `[5:0]` که یه بازه‌ی معکوس و همیشه خالیه.

**درسش:** وقتی داری با اسلایسینگ (`[start:stop]`) کار می‌کنی، همیشه جهت بازه رو چک کن — اگه بخوای «تا آخر لیست» بگی، `stop` رو کامل خالی بذار (`[n:]`)؛ عدد صفر گذاشتن اونجا معنی «تا اول لیست» می‌ده، نه «تا آخر».

## 📌 درس کلی از همه این باگ‌ها

بیشتر مشکلات یا از **مسیر اشتباه** (پوشه به‌جای فایل اجرایی) بودن، یا از **اسم اشتباه** (پکیج یا مدل درست انتخاب نشده بود)، یا از **محدودیت بیرونی** (منطقه یا موجودی مدل)، یا از **منطق خود کد** (شرط برعکس، ساختار داده اشتباه) که ربطی به سرویس بیرونی نداشت. برای دیباگ بعدی، همیشه اول این سوال‌ها رو از خودم بپرسم:

1. آیا مسیری که دادم دقیقاً به فایل درست اشاره می‌کنه؟
2. آیا اسمی که استفاده کردم (پکیج، مدل) دقیقاً همونیه که باید باشه؟
3. آیا خطا از کد منه، یا از یه محدودیت بیرونی (سرویس، شبکه، حساب)؟
4. اگه از کد خودمه، آیا منطق شرط‌هام (`>` یا `<=`) و ساختار داده‌هام (لیست تو لیست یا چسبیده) درسته؟

## 🔢 کدهای خطای وب که با این پروژه زیاد می‌بینی

هر بار که با یه سرویس آنلاین (مثل گراک یا OpenRouter) کار می‌کنی، جواب همیشه یه «کد وضعیت» سه‌رقمی داره. این کد اولین چیزیه که باید نگاه کنی، حتی قبل از خوندن متن پیام خطا — چون خودش می‌گه مشکل کجاست.

|کد|اسم|یعنی چی|تو این پروژه کِی دیدیمش|
|---|---|---|---|
|**۴۰۰**|Bad Request|چیزی که فرستادی از نظر ساختار غلطه — سرور اصلاً نفهمید چی خواستی|وقتی `messages=message` (مفرد) فرستادم به‌جای لیست کامل؛ و وقتی `trim_messages` ساختار `messages` رو خراب کرد|
|**۴۰۱**|Unauthorized|کلید API اشتباهه، خالیه، یا اصلاً نفرستادیش|(تو این پروژه ندیدیم، ولی یعنی کلیدت مشکل داره)|
|**۴۰۳**|Forbidden|کلید درسته، ولی دسترسی بهت داده نمی‌شه — معمولاً یعنی محدودیت منطقه‌ای یا محدودیت حساب|وقتی گراک از منطقه من دسترسی نمی‌داد|
|**۴۰۴**|Not Found|چیزی که خواستی (مثلاً اسم مدل) اصلاً وجود نداره یا دیگه در دسترس نیست|وقتی مدل رایگان دیگه موجود نبود|
|**۴۲۹**|Too Many Requests|سهمیه یا نرخ درخواست پر شده — یا مال خودت یا مال یه استخر مشترک|وقتی مدل رایگان شلوغ بود (دوبار، با دو مدل مختلف)|
|**۵۰۰ به بالا**|Server Error|مشکل از سمت خود سرویسه، نه از کد تو — معمولاً فقط باید صبر کنی و دوباره امتحان کنی|(تو این پروژه ندیدیم)|

**نکته کلیدی برای تشخیص سریع:** کدهای ۴xx یعنی مشکل احتمالاً از طرف توئه (کد، اسم، یا مسیر اشتباه) — کدهای ۵xx یعنی مشکل از طرف سرویسه و صبر کردن یا امتحان‌کردن یه سرویس دیگه راه‌حله.

## 🔍 از این به بعد خودم چطور ارور رو بخونم؟

هر بار پایتون یه ارور طولانی (Traceback) نشون می‌ده، این ترتیب رو دنبال کن:

۱. **از پایین شروع کن، نه از بالا.** خط آخر همیشه خلاصه ارور واقعیه (مثل `openai.NotFoundError: ...`). خط‌های بالاش فقط مسیریه که کد طی کرده تا به اون ارور برسه.

۲. **دنبال اسم فایل خودت بگرد.** تو Traceback چند تا فایل می‌بینی — بعضی‌هاشون مال خود کتابخونه‌ست (مثل `openai/_base_client.py`)، ولی حتماً یه خط با اسم فایل خودت هست (مثل `chat_bot.py`). دقیقاً همون خط، محل واقعی مشکله — بقیه فایل‌ها فقط دارن اون خط رو اجرا می‌کنن.

۳. **کد وضعیت رو تو جدول بالا پیدا کن** تا بفهمی دسته‌بندی کلی مشکل چیه (از طرف تو یا از طرف سرویس).

۴. **متن دقیق پیام خطا رو بخون، نه فقط کدش.** خیلی وقت‌ها (مثل باگ ۶ و ۹) خودِ سرویس دقیقاً می‌گه چیکار کنی یا کجای داده‌ت خرابه.

۵. **اگه هنوز معلوم نبود، همون متن دقیق پیام خطا رو جستجو کن** (بدون تغییر، عین همون کلمه‌ها) — چون معمولاً یه نفر دیگه هم قبلاً همین ارور رو گرفته.
